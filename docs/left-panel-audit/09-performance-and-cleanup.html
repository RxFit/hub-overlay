Left-Panel Audit 09 — Performance polish & cleanup P2

Summary. A focused cleanup pass over the left-panel render path and its supporting libraries. It removes the last avoidable render churn (KPI numbers re-animating on every poll tick, one unmemoized derived list in the Tasks section), deletes dead imports / dead default arguments / a structural type gap, and corrects one UI affordance that over-promises (the Tasks + Task button is styled like an inline creator but only injects a chat message). All items are low-risk and self-contained. No data-fetching behavior, no API contracts, and no styling tokens change.

This plan was written against current master (HEAD = f8ae3ad, "Left-panel 06"). Each finding below was re-verified on the merged code from PRs #14–#19 (plans 01–06); items those PRs already fixed are marked Already fixed and are not re-implemented here.

Why this matters

  • Perceived jank & wasted CPU. KPI numbers run a 900 ms requestAnimationFrame count-up. Because the effect keys on the value string identity, every 60 s data poll re-fires the count-up (and re-runs the staggered fade-in) even when the underlying number is unchanged. The user sees the whole KPI grid "flicker and recount" on a silent refresh. Plan 06 memoized the four sections, which cuts structural re-renders, but the effect still re-runs whenever a new value string of equal content arrives — the guard has to live inside the component.
  • Render efficiency. The Tasks section recomputes its filtered task list on every render via a bare .filter(). It is cheap per call but it is the only section that wasn't tidied in plan 06; bringing it in line keeps the pattern consistent and avoids needless allocation while toggling tasks optimistically.
  • Maintainability. Dead imports, a dead default argument, and a structural input type that doesn't mirror the real shape are small individually, but they mislead the next reader and quietly defeat noUnusedLocals / review signal. Cleaning them now is nearly free.
  • Honest affordances. A button labeled + Task with a "Create task in…" tooltip sets the expectation of inline creation, but it only drops a chat message. Relabeling it to "Ask AI to add a task" makes the behavior truthful with zero functional risk. Building a real inline-create form is a larger product decision and is explicitly deferred.

Implementation

Change 1 — Guard the KPI count-up so it only runs on first mount or a real value change

File: hub/app/components/AnimatedNumber.tsx

Add a useRef import and two refs: one to track whether the stagger has already played (so the fade-in runs once on first appearance only), and one to track the last value we actually animated to (so the count-up only fires when the displayed numeric value genuinely changes). On a poll that returns the same value, both effects become no-ops and the rendered number stays put.

// lines 3 / 10–40 (current)
import { useState, useEffect } from 'react'

export function AnimatedNumber({ value, delay = 0 }: { value: string; delay?: number }) {
  const [visible, setVisible] = useState(false)
  const [displayed, setDisplayed] = useState('0')

  useEffect(() => {
    const t = setTimeout(() => setVisible(true), delay)
    return () => clearTimeout(t)
  }, [delay])

  useEffect(() => {
    if (!visible) return
    const numMatch = value.match(/^(\$?)(\d[\d,]*)(.*)$/)
    if (!numMatch) { setDisplayed(value); return }
    const prefix = numMatch[1]
    const rawNum = parseInt(numMatch[2].replace(/,/g, ''), 10)
    const suffix = numMatch[3]
    if (isNaN(rawNum) || rawNum === 0) { setDisplayed(value); return }
    const duration = 900
    const startTime = performance.now()
    const tick = (now: number) => {
      const elapsed = now - startTime
      const progress = Math.min(elapsed / duration, 1)
      const eased = 1 - Math.pow(1 - progress, 3)
      const current = Math.round(eased * rawNum)
      const formatted = prefix + current.toLocaleString() + suffix
      setDisplayed(formatted)
      if (progress < 1) requestAnimationFrame(tick)
      else setDisplayed(value)
    }
    requestAnimationFrame(tick)
  }, [visible, value])
// after
import { useState, useEffect, useRef } from 'react'

export function AnimatedNumber({ value, delay = 0 }: { value: string; delay?: number }) {
  const [visible, setVisible] = useState(false)
  const [displayed, setDisplayed] = useState('0')

  // Play the staggered fade-in ONCE, on first appearance only — not on every
  // poll that hands us a fresh-but-equal `value` string.
  const hasAppeared = useRef(false)
  // The value we last animated TO. A 60s poll that returns the same number
  // leaves this unchanged, so the count-up below short-circuits and the KPI
  // grid stays still instead of re-counting on every tick.
  const lastAnimatedValue = useRef<string | null>(null)

  useEffect(() => {
    if (hasAppeared.current) { setVisible(true); return }
    const t = setTimeout(() => { hasAppeared.current = true; setVisible(true) }, delay)
    return () => clearTimeout(t)
  }, [delay])

  useEffect(() => {
    if (!visible) return
    // Only animate on first mount or a genuine value change.
    if (lastAnimatedValue.current === value) return
    lastAnimatedValue.current = value

    const numMatch = value.match(/^(\$?)(\d[\d,]*)(.*)$/)
    if (!numMatch) { setDisplayed(value); return }
    const prefix = numMatch[1]
    const rawNum = parseInt(numMatch[2].replace(/,/g, ''), 10)
    const suffix = numMatch[3]
    if (isNaN(rawNum) || rawNum === 0) { setDisplayed(value); return }
    const duration = 900
    const startTime = performance.now()
    const tick = (now: number) => {
      const elapsed = now - startTime
      const progress = Math.min(elapsed / duration, 1)
      const eased = 1 - Math.pow(1 - progress, 3)
      const current = Math.round(eased * rawNum)
      const formatted = prefix + current.toLocaleString() + suffix
      setDisplayed(formatted)
      if (progress < 1) requestAnimationFrame(tick)
      else setDisplayed(value)
    }
    requestAnimationFrame(tick)
  }, [visible, value])

Rationale. Refs are mutated synchronously and don't trigger re-renders, so the guards add no churn of their own. hasAppeared makes the delay stagger a one-time entrance; once it has played, a later re-render (e.g. the component staying mounted across a poll) sets visible immediately without re-staggering. lastAnimatedValue makes the count-up idempotent for equal values: the first time a number arrives it animates; an identical poll result is a no-op; a real change re-animates from the current display. Note the initial value of lastAnimatedValue is null, so the very first non-empty value always animates.

Change 2 — Memoize the Tasks filtered list

File: hub/app/components/LeftPanelSections.tsx (TasksSectionBody, lines 278–279). useMemo is already imported (line 3).

Wrap the two derived values in a single useMemo keyed on the inputs that actually feed them. Because renderSectionState returns early above this point (line 273–276), the memo must sit after that guard is fine — hooks here run before the early return only if placed above it.
