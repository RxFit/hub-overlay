Left Panel Audit — Remediation Plans

This directory holds the implementation plans produced from a full audit of the hub's left panel interface (KPIs, Calendar, Tasks, Documents, and the panel shell), the inject→chat plumbing, the backing API routes/SWR hooks, and the mobile drawer. The audit was triggered by a reported P0: clicking a Google Drive document shows “Something went wrong on my end.”

The findings are grouped into six independently-shippable pieces of work, each with its own plan file detailed enough to start a PR from (problem, line-referenced findings, before/after changes, tests, acceptance criteria, sequencing, rollback). They are ordered by priority and intended to land in sequence.

The pieces

#PlanPriorityWhat it fixes
1 Document click & chat error visibility P0 The reported bug. Wrap /api/chat so unguarded getServerSession/getToken throws return a logged JSON 500 instead of an opaque framework 500; make the client surface server details and distinguish 401/5xx/timeout; cap the document path’s extra Vertex call and the un-timed Drive export; clearer missing-token message.
2 Error masking & auth recovery P0 Stop fetch/401 failures rendering as misleading “empty / not configured” states (KPI section ignores error; KPI/artifacts/tasks fetchers drop HTTP status so reauth never fires); revive the dead useAuthErrorRecovery path with one consistent “Sign in again” UX; make write mutations check res.ok and handle 401 reauth.
3 Calendar & Tasks data integrity P0 Event location silently dropped on create; dateTime sent with no timeZone (wrong hour); toISOString date off-by-one for Central-time users; future task due dates render “just now”; missing summary fallback.
4 Documents / Drive multi-tenant & waste P1 Hardcoded transcripts folder ID breaks every other account; Artifacts tab fires a wasted Drive poll; useDrive has no mutate/retry; artifact tap carries no id; “Invalid Date” on bad createdAt.
5 Polling cost & data-layer consolidation P1 Collapsed sections keep polling; Tasks does N+1 every 30s; useKPIData subscribed twice; unread-counts runs a manual fetch loop bypassing SWR; SWR config drift.
6 Drawer resilience, a11y & mobile P0 P1 No error boundary (one section throw blanks the whole app); mobile drawer has no dialog role / focus trap / Escape / scroll-lock; sections unmemoized; heading & landmark a11y; keyboard-inaccessible task rows.
7 Inject-path unification P1 Panel taps call sendToApi directly, bypassing doSend — so a “create task/event” tap never triggers Interview Mode like typed text does. Also: onInjectChat signature drift across sections, and the 5-attachment cap not enforced on the inject path.
8 Accessibility completion P2 The parts piece 6 didn’t cover: create/delete modal focus-trap/Escape/restore, ARIA tab & listbox keyboard patterns (Documents/Tasks tabs, Calendar week strip), KPI-card redundant aria-labels, and listitem-role-on-button.
9 Performance & cleanup P2 AnimatedNumber re-animating on every poll; memoize the leftover Tasks list; dead-code removal (unused imports, dead useCase default, DriveFileInput.modifiedTime); relabel the over-promising “+ Task” FAB.

Status. Pieces 1–6 are implemented and merged to master (PRs #14–#19). Pieces 7–9 are the follow-up polish round (the inject-path architecture fix plus the P2 accessibility/performance items the first six didn’t cover); plans 8 and 9 were verified against the post-merge master and exclude anything 1–6 already fixed.

Suggested sequencing

Land in numeric order. A few cross-dependencies to respect:

  • Plan 1 first — it restores the reported bug and, critically, makes every future chat failure diagnosable (top-level try/catch + client surfacing of details). Everything else is easier to verify once failures stop being opaque.
  • Plans 2 and 5 touch the same KPI data wiring. Plan 2 adds error handling to KPISection; Plan 5 lifts useKPIData to HubPage and makes KPISection props-driven. If Plan 5 lands after Plan 2, thread the error prop through at that point (called out in both plans’ sequencing sections).
  • Plan 6’s error boundary pairs well with Plan 2 — together they ensure a section degrades to an inline error rather than a blank app or a misleading empty state.
How these were produced. Five parallel auditors swept the panel (document-bug root cause, Documents, Calendar+Tasks, KPI+data-layer, and cross-cutting concerns). Each plan was written by a dedicated agent that re-opened the referenced files and corrected line numbers against the live code before writing. Severity tags: P0 critical · P1 important · P2 polish.
