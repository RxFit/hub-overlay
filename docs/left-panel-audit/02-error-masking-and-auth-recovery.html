Stop “empty-on-error” masking + unify auth recovery P0

Across the Left Panel, fetch and auth failures render as misleading “empty / not-configured” states, and the documented 401→reauth path is non-functional. This plan eliminates the masking, makes every section’s error and auth-error states honest and consistent, fixes the fetchers that silently drop the HTTP status (so a 401 can actually be detected), and replaces the dead useAuthErrorRecovery hook with a single, accessible, actionable reauth UX (a real “Sign in again” button). It also hardens the write mutations (toggle task, delete event, create event) so they stop reporting success on failure and route 401 responses into the same reauth flow.

All line numbers and snippets below were verified against the working tree on 2026-06-24. Paths are relative to the repo root /home/user/hub-overlay; the Next.js app lives under hub/.

Why this matters

  • Silent data loss looks like “nothing here”. When the KPI or Documents-artifacts fetch fails (network, 500, or an expired Google/Paperclip session), the user sees “No business KPIs configured” or an empty artifacts tab. They conclude the feature is unconfigured or empty and stop using it — the worst possible failure mode for a dashboard.
  • The self-healing auth path is wired to a switch that is never thrown. The route layer already maps Google auth failures to 401 { reauth: true } (hub/lib/google-session.ts), and useHubData.ts’s fetcher tags those errors with .status = 401. But useKPIData.ts and the Documents-artifacts fetcher throw plain Errors with no .status, so the section-level (error as any).status === 401 checks can never match. KPI 401s are indistinguishable from “empty”.
  • Reauth is dead code. useAuthErrorRecovery (which auto-calls signIn('google') on a 401) has zero call sites — verified by grep, it is only defined, never imported. The sections that do detect a 401 render a static “Session expired — please sign in again” string with no button, so the user has no way to actually re-authenticate from the panel.
  • Writes lie about success. handleToggleTask, handleDeleteConfirm, and the calendar create-modal handleSave either ignore res.ok entirely or (for create) check it but never handle the 401 { reauth: true } contract. A toggle/delete against an expired session resolves “successfully”, the optimistic UI sticks, and the change is silently lost on the next refresh.
  • The same 401 string is copy-pasted in three places with subtly different logic. Extracting one shared state renderer removes the drift and guarantees every section behaves identically.

async function fetcher(url: string) {
  const res = await fetch(url)
  if (!res.ok) {
    const errorData = await res.json().catch(() => ({}))
    const err = new Error(errorData.error || `API error ${res.status}`)
    ;(err as any).status = res.status
    throw err
  }
  return res.json()
}

Rationale: Mirrors the useHubData.ts fetcher (32–49) so a KPI 401 carries error.status === 401 and can be distinguished from a generic error and from “empty”. This is the keystone fix — F1 cannot work without it.

Change 4 — F5: Replace the dead hook with an actionable reauth control

Decision: Adopt a single reauth UX everywhere — an accessible “Sign in again” button rendered inside the auth-error message. This is preferred over the silent auto-redirect in useAuthErrorRecovery because it is explicit, accessible (focusable, announced), and does not yank the user mid-task. We extend SectionMessage to accept an optional action; the shared renderer (Change 5) wires it up so all sections are consistent.

Change 5 — F7: Extract a shared renderSectionState helper

File: hub/app/components/LeftPanelSections.tsx — add once, just after SectionMessage (after line 56).

/**
 * Shared loading / auth-error / error renderer for Left Panel sections.
 * Returns the element to render, or null when there is no blocking state
 * (i.e. the section should render its real content).
 *
 *   const state = renderSectionState({ isLoading, error, skeletonLines: 4 })
 *   if (state) return <CollapsibleSection ...>{state}</CollapsibleSection>
 */
function renderSectionState({
  isLoading,
  error,
  skeletonLines = 3,
}: {
  isLoading?: boolean
  error?: unknown
  skeletonLines?: number
}): ReactNode | null {
  if (isLoading) return <SkeletonBlock lines={skeletonLines} />

  if (error) {
    const isAuthError = (error as any)?.status === 401
    if (isAuthError) {
      return (
        <SectionMessage
          message="Session expired — please sign in again"
          type="error"
          action={{ label: 'Sign in again', onClick: () => signIn('google') }}
        />
      )
    }
    return <SectionMessage message="Something went wrong — try refreshing" type="error" />
  }

  return null
}

Rationale: Single source of truth for the skeleton / 401 / generic-error ladder. The 401 branch always carries the reauth button. Generic-error copy is centralized (individual sections may still override by not using the helper, but the goal is uniformity). Sections keep ownership of their empty state (which is content-specific) and only delegate the loading/error states.

Change 7 — F6: A shared writeFetch helper + hardened mutations

File: add hub/app/hooks/useWriteFetch.ts (or co-locate in an existing client util). It wraps fetch for write requests, detects the 401 { reauth: true } contract from hub/lib/google-session.ts (43–53), routes to reauth, and throws a status-tagged error otherwise. 

'use client'
import { signIn } from 'next-auth/react'

/**
 * Fetch wrapper for write mutations (POST/DELETE/PUT).
 * - On 401 { reauth: true } (or any 401), triggers Google re-auth and throws.
 * - On any other !res.ok, throws an Error carrying `.status`.
 * - On success, returns the parsed JSON (or {} if no body).
 * Routes that fail Google auth return 401 { reauth: true } via
 * lib/google-session.ts → googleApiErrorResponse / resolveGoogleAuth.
 */
export async function writeFetch<T = any>(input: RequestInfo, init?: RequestInit): Promise<T> {
  const res = await fetch(input, init)
  if (res.status === 401) {
    const body = await res.json().catch(() => ({}))
    // Honor the explicit reauth contract; default to reauth on any 401.
    if (body?.reauth !== false) signIn('google')
    const err = new Error(body?.error || 'Session expired — please sign in again')
    ;(err as any).status = 401
    throw err
  }
  if (!res.ok) {
    const body = await res.json().catch(() => ({}))
    const err = new Error(body?.error || `Request failed (${res.status})`)
    ;(err as any).status = res.status
    throw err
  }
  return res.json().catch(() => ({} as T))
}
