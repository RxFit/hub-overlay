Documents / Drive: multi-tenant correctness + eliminate waste P1

Scope: the Documents section of the left panel — its API route (hub/app/api/google/drive/route.ts), its SWR hook (hub/app/hooks/useHubData.ts → useDrive), and its renderer (hub/app/components/LeftPanelSections.tsx → DocumentsSection / DocumentRow).

Summary: The Documents feature has one multi-tenant correctness bug and a cluster of waste / robustness issues. The Transcripts filter hardcodes a single Google Drive folder id, so it only works for the one account that owns that folder — every other tenant and user gets that owner's transcripts (a cross-tenant data exposure) or nothing. Separately, the Artifacts tab still fetches and 120s-polls Drive "recent" files it never renders; the Drive hook exposes no mutate so its error UI has no retry; tapped artifacts inject only toolId + title (dropping the real artifact.id that is right there as the React key); an unguarded new Date(...).toLocaleDateString() can print "Invalid Date"; the empty-state copy doesn't match the 7-day query window; and per-render icon maps plus an unmemoized row recompute on every poll. This plan fixes all of them without touching unrelated sections.

Why this matters

  • Cross-tenant data exposure (P1-5). The codebase is explicitly multi-tenant (getTenantId() is the single source of truth, used across artifacts, KPIs, memory, events) and Drive auth is per-user OAuth. Hardcoding one folder id means the Transcripts tab is either broken (the folder isn't visible to this user's token → empty/error) or, worse, surfaces another tenant's meeting transcripts. This is the only correctness/security defect in the group and is the reason the piece is P1.
  • Silent background waste (P1-2). On the Artifacts tab the Drive hook keeps a 120s poll alive against /api/google/drive?filter=recent whose results are never rendered — needless Google Drive API quota burn and a request that shows up in every session's Network tab.
  • No recovery path (P1-3). useDrive sets revalidateOnFocus:false and returns no mutate, so a transient Drive failure is terminal until a full reload. The error copy literally says "try refreshing" but the UI gives the user no button to do so.
  • Ambiguous artifact resolution (P1-4). Injecting only toolId + title makes two artifacts with the same tool and title indistinguishable. The unique artifact.id is already in hand (it's the list key) and the document path already demonstrates the structured-attachment pattern via buildDocumentInject.
  • Polish / correctness-at-the-edges (P1-7, P2-8/9/10). "Invalid Date" on malformed timestamps, copy that contradicts the actual query window, and avoidable per-poll re-computation are all cheap to fix while we're in the file.

/** Build the Drive query string based on filter type */
function buildDriveQuery(filter: string | null, customQ?: string): string | undefined {
  const sevenDaysAgo = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000).toISOString()

  switch (filter) {
    case 'shared':
      return `sharedWithMe = true and modifiedTime > '${sevenDaysAgo}' and ${VIDEO_EXCLUSIONS}`

    case 'transcripts':
      return `'1PQ47SWRWn-A1dToniwglJy9uqEwZSVwA' in parents`

    case 'recent':
    default: {
      // Default "recent" query: files I modified, excluding videos
      const base = customQ
        ? `${customQ} and ${VIDEO_EXCLUSIONS}`
        : `modifiedTime > '${sevenDaysAgo}' and ${VIDEO_EXCLUSIONS}`
      return base
    }
  }
}
/** Result of building a Drive query.
 *  - { query }            → run this query
 *  - { empty: true }      → return an empty file list without calling Drive */
type DriveQueryPlan = { query?: string; empty?: boolean }

/** Build the Drive query plan based on filter type and the active tenant. */
function buildDriveQuery(
  filter: string | null,
  customQ: string | undefined,
  transcriptsFolderId: string | undefined,
): DriveQueryPlan {
  const sevenDaysAgo = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000).toISOString()

  switch (filter) {
    case 'shared':
      return { query: `sharedWithMe = true and modifiedTime > '${sevenDaysAgo}' and ${VIDEO_EXCLUSIONS}` }

    case 'transcripts':
      // Per-tenant folder; no hardcoded id. Unconfigured → empty (no cross-tenant leak).
      if (!transcriptsFolderId) return { empty: true }
      return { query: `'${transcriptsFolderId}' in parents and ${VIDEO_EXCLUSIONS}` }

    case 'recent':
    default: {
      // Default "recent" query: files I modified, excluding videos
      const base = customQ
        ? `${customQ} and ${VIDEO_EXCLUSIONS}`
        : `modifiedTime > '${sevenDaysAgo}' and ${VIDEO_EXCLUSIONS}`
      return { query: base }
    }
  }
}

export interface ArtifactInput {
  id: string
  toolId: string
  title: string
}

/**
 * Build the message + attachment for a tapped tool artifact. The attachment
 * carries the real artifact id so the chat route resolves THIS artifact even
 * when two share a toolId + title.
 */
export function buildArtifactInject(
  artifact: ArtifactInput,
): { message: string; attachment: ChatAttachment } {
  const message = `Show me the ${artifact.toolId} artifact: ${artifact.title}`
  const attachment: ChatAttachment = {
    id: artifact.id,
    type: 'text',
    label: artifact.title,
    // Embed the resolvable id so the chat route can fetch the artifact by id.
    content: `[artifact:${artifact.id}] toolId=${artifact.toolId} title="${artifact.title}"`,
  }
  return { message, attachment }
}

  • Artifact date rendering uses formatShortDate and never prints "Invalid Date".
