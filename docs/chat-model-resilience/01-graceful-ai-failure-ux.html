Graceful AI-failure messaging  P2

Summary

When the AI model layer fails — an invalid provider key, a provider rate-limit, or the “all models in cooldown” state — the chat currently leaks the raw provider error straight into the conversation bubble. Users see strings like: 

⚠ [GoogleGenerativeAI Error]: Error fetching from https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:streamGenerateContent: [400 Bad Request] API key not valid. Please pass a valid API key.
⚠ All models are in cooldown

These messages are non-actionable for an end user and expose internal endpoints, model ids, and provider mechanics. This piece maps model-layer failures to a small set of clean, calm, actionable user-facing messages, while preserving the real error in the server logs (Cloud Run) for operators.

Scope caveat — this is UX / resilience ONLY. It does not restore AI answers. Restoring answers requires valid provider API keys (Anthropic as the primary provider, Gemini as the fallback), which is an environment / Secret-Manager concern that lives outside this repo. This change just makes failures legible: instead of a wall of provider internals, the user gets a short, honest, retry-friendly message and the operator still gets the full stack in the logs.

Why this matters

  • User trust & clarity. A raw 400 Bad Request ... API key not valid reads like a bug the user caused. A calm “temporarily unavailable, try again shortly” is honest and non-alarming.
  • Information disclosure. The current path leaks the provider, the model id (gemini-2.5-pro), the API endpoint, and the failure category to anyone in the chat. None of that is actionable or appropriate for an end user.
  • Operability. Today the raw message goes to the client but is not guaranteed in structured server logs at the stream-catch boundary. After this change the raw error is always logged server-side via the existing createLogger('chat') logger, so on-call can see exactly which provider/key failed.
  • Cheap and orthogonal. No new dependencies, no schema changes; it is independent of the actual key fix and can ship before or after it.

Implementation

Change 1 — Add friendlyModelError() helper in hub/lib/gemini.ts

File: hub/lib/gemini.ts — add an exported function next to the existing classifiers (immediately after isAuthOrKeyError, i.e. after line 317).

Precedence (decided): check auth/key first, then rate-limit, then fall back to a generic retry. The 'cooldown' string is handled by routing it to the rate-limit / busy message by default (a cooldown is fundamentally “try again later”). We do not try to distinguish “cooldown caused by a key failure” from the opaque 'All models are in cooldown' string, because that string carries no auth signal — attributing it to a config problem would be a guess. Auth attribution stays driven by isAuthOrKeyError matching the real provider error text, which does reach this helper on the common single-provider-key-bad path (Gemini re-throws the auth error at line 523, and the Claude chain’s auth break still lets the Gemini auth error surface).

Before (lines 307–317, unchanged — shown for anchor):

export function isAuthOrKeyError(err: unknown): boolean {
  const msg = (err instanceof Error ? err.message : String(err)).toLowerCase()
  return /(^|\D)(401|403)(\D|$)/.test(msg)
    || msg.includes('api key')
    || msg.includes('api_key')
    || msg.includes('permission')
    || msg.includes('unauthenticated')
    || msg.includes('unauthorized')
    || msg.includes('invalid key')
    || msg.includes('billing')
}

After — insert the following directly below that function:

/**
 * Maps a raw model-layer failure to a calm, actionable, non-leaky message for
 * the end user. The RAW error is logged server-side by the caller (route.ts);
 * this string is the ONLY thing that should ever reach the chat bubble.
 *
 * Precedence: auth/config > rate-limit/busy > generic retry.
 * Never interpolates err.message, so provider internals (endpoints, model ids,
 * "API key not valid", stack frames) can never leak through.
 */
export function friendlyModelError(err: unknown): string {
  const msg = (err instanceof Error ? err.message : String(err)).toLowerCase()

  // Auth / key / billing / permission: a shared-credential problem the user
  // can't fix. Frame it as a provider-config issue and point at an admin.
  if (isAuthOrKeyError(err)) {
    return 'The AI service is temporarily unavailable (provider configuration). '
      + 'Please try again shortly — if it persists, contact an administrator.'
  }

  // Rate limits, overload, quota, or the "all models in cooldown" backoff state:
  // transient. Tell the user to retry in a moment.
  if (isRateLimitError(err) || msg.includes('cooldown')) {
    return 'The AI is busy right now. Please try again in a moment.'
  }

  // Anything else (timeouts, 5xx, malformed-stream, unknown): generic retry.
  return "The AI couldn't complete that response. Please try again."
}

Rationale. A pure, side-effect-free mapping function is trivially unit-testable and has a single responsibility. It reuses the two existing classifiers verbatim so the matching logic stays in one place. It never reads err.message into its output, which is the property that guarantees no provider string leaks.

Change 3 — (Secondary, recommended) longer skip for auth-failed models in gemini.ts

File: hub/lib/gemini.ts — the Gemini fallback failure handler around lines 512–528.

Goal: a permanently-bad fallback key should not be re-attempted on every single request. Today, a non-rate-limit failure (which includes auth) records a 5-minute cooldown via recordModelFailure(modelName, false) (line 514), and then auth fast-fails by re-throwing (line 523). That re-throw behavior is correct and must be preserved. The refinement is purely to lengthen the cooldown bookkeeping for an auth-failed model so it stops dominating the “all models in cooldown” churn, without altering control flow.

Before (lines 512–529):

    } catch (err) {
      const isRateLimit = isRateLimitError(err)
      recordModelFailure(modelName, isRateLimit)

      // Mid-stream failure after emitting text: rotating restarts the answer and
      // duplicates it on the wire. Propagate instead.
      if (emittedAny) throw err

      // Auth/key/permission/billing errors share the credential across every
      // model — the next model can't succeed, so fail fast instead of burning
      // the 2 s fallback delay.
      if (isAuthOrKeyError(err)) throw err

      if (isLastAttempt) {
        throw err // All approved models exhausted
      }
      console.warn(`[gemini] ${modelName} failed (${isRateLimit ? 'rate_limit' : 'error'}), falling back to ${modelsToTry[i + 1]}:`, err)
    }

After — add an auth argument to recordModelFailure and pass it; control flow is untouched:

    } catch (err) {
      const isRateLimit = isRateLimitError(err)
      const isAuth = isAuthOrKeyError(err)
      // Auth-failed models get a longer "unavailable" skip (see recordModelFailure):
      // a permanently-bad key shouldn't be re-attempted every request.
      recordModelFailure(modelName, isRateLimit, isAuth)

      // Mid-stream failure after emitting text: rotating restarts the answer and
      // duplicates it on the wire. Propagate instead.
      if (emittedAny) throw err

      // Auth/key/permission/billing errors share the credential across every
      // model — the next model can't succeed, so fail fast instead of burning
      // the 2 s fallback delay.
      if (isAuth) throw err

      if (isLastAttempt) {
        throw err // All approved models exhausted
      }
      console.warn(`[gemini] ${modelName} failed (${isRateLimit ? 'rate_limit' : 'error'}), falling back to ${modelsToTry[i + 1]}:`, err)
    }

And update recordModelFailure (lines 361–365) to accept the optional flag. The default preserves today’s exact behavior (third argument absent ⇒ unchanged), which keeps the existing Claude call site at line 412 and all current tests green.

Before (lines 361–365):

function recordModelFailure(model: string, isRateLimit: boolean): void {
  // W-2 FIX: Rate limits get shorter cooldown (30s), real failures get 5 min
  const cooldownMs = isRateLimit ? 30_000 : 300_000

After:

function recordModelFailure(model: string, isRateLimit: boolean, isAuth: boolean = false): void {
  // W-2 FIX: Rate limits get shorter cooldown (30s), real failures get 5 min.
  // Auth/key failures are not transient — a bad/absent credential won't heal in
  // 5 min, so give it a much longer skip (30 min) to stop hammering a dead key
  // on every request and to keep it out of the rotation's churn.
  const cooldownMs = isAuth ? 1_800_000 : isRateLimit ? 30_000 : 300_000
  _modelCooldowns.set(model, { failedAt: Date.now(), cooldownMs })
}

Rationale & safety notes.

  • The isAuth parameter is optional with a false default, so the existing Claude-chain call recordModelFailure(claudeModel, isRateLimit) (line 412) compiles and behaves identically. No other call sites change.
  • The Gemini auth re-throw / fast-fail is preserved — if (isAuth) throw err is the same control flow as before (we only renamed the inline isAuthOrKeyError(err) call into the isAuth local). This change is bookkeeping-only.
  • This is genuinely optional. If the reviewer prefers a smaller diff, ship Changes 1–2 alone; the user-facing messaging fix does not depend on Change 3.
  • Because recordModelFailure / isModelInCooldown / _modelCooldowns are module-private and tests exercise behavior (not the cooldown constant directly), no existing test asserts the literal 300_000 value — verify with npx vitest run after the change.

describe('friendlyModelError — user-facing message mapping', () => {
  it('maps auth/key/config failures to the config message', () => {
    const authMsg = 'The AI service is temporarily unavailable (provider configuration). '
      + 'Please try again shortly — if it persists, contact an administrator.'
    for (const m of [
      '[GoogleGenerativeAI Error]: [400 Bad Request] API key not valid. Please pass a valid API key.',
      'HTTP 401 Unauthorized',
      'status 403',
      'permission denied',
      'billing disabled',
    ]) {
      expect(friendlyModelError(new Error(m))).toBe(authMsg)
    }
  })

  it('maps rate-limit / busy / cooldown failures to the busy message', () => {
    const busyMsg = 'The AI is busy right now. Please try again in a moment.'
    for (const m of ['HTTP 429', 'model overloaded', 'quota exceeded', 'All models are in cooldown']) {
      expect(friendlyModelError(new Error(m))).toBe(busyMsg)
    }
  })

  it('maps unknown/generic failures to the retry message', () => {
    const retryMsg = "The AI couldn't complete that response. Please try again."
    for (const m of ['Gemini stream timeout (gemini-2.5-pro)', '500 internal error', 'something exploded']) {
      expect(friendlyModelError(new Error(m))).toBe(retryMsg)
    }
    // Non-Error inputs are handled too.
    expect(friendlyModelError('boom')).toBe(retryMsg)
    expect(friendlyModelError(undefined)).toBe(retryMsg)
  })

  it('auth takes precedence over rate-limit when both could match', () => {
    // A message containing both an auth and a rate-limit signal resolves to config.
    const out = friendlyModelError(new Error('401 unauthorized — also rate limit'))
    expect(out).toContain('provider configuration')
  })

  it('never leaks raw provider internals into the output', () => {
    const leaky = '[GoogleGenerativeAI Error]: Error fetching from '
      + 'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:streamGenerateContent: '
      + '[400 Bad Request] API key not valid. Please pass a valid API key.'
    const out = friendlyModelError(new Error(leaky))
    for (const needle of [
      'GoogleGenerativeAI', 'generativelanguage', 'gemini-2.5-pro',
      'streamGenerateContent', '400', 'API key not valid', 'https',
    ]) {
      expect(out).not.toContain(needle)
    }
  })
})

Rationale. The leak-prevention test is the load-bearing one: it asserts that none of the raw provider tokens from the real-world error survive into the mapped string. The precedence test pins the documented auth-over-rate-limit ordering so a future refactor can’t silently flip it.

Acceptance criteria

  • No raw provider string (GoogleGenerativeAI, endpoint URLs, gemini-2.5-pro, API key not valid, HTTP status codes, stack frames) ever reaches the chat bubble.
  • Auth/key/billing/permission failures → the “provider configuration… contact an administrator” message.
  • Rate-limit / overload / quota / cooldown failures → the “AI is busy… try again in a moment” message.
  • All other failures → the generic “couldn’t complete that response… try again” message.
  • The raw error is always written to the server logs at the stream-catch boundary via log.error({ err }, 'Chat stream failed').
  • Partial-text preservation is unaffected: if a model streamed tokens then failed, the friendly message is appended below the partial text (existing client behavior, F4).
  • npx tsc --noEmit passes; npx vitest run is green, including the new tests and all pre-existing rotation/cooldown/auth tests.
  • (Change 3, if included) the Gemini auth fast-fail re-throw still fires; existing tests still pass.

Dependencies & sequencing

  • Independent of the environment key fix. This piece is orthogonal to provisioning valid Anthropic/Gemini keys in Secret Manager. It can ship before, after, or instead of that work — it changes only how failures read, not whether the AI answers.
  • Internal order: Change 1 (helper) must land before Change 2 (which imports it) and Change 4 (which tests it). Change 3 is optional and independent of 1/2/4.
  • No new packages, no migrations, no config changes, no client deploy coupling.

Rollback

  • Low risk and trivially reversible. Revert the commit, or individually: restore the two lines in the route.ts catch block (raw err.message + drop the log.error), and remove friendlyModelError and its import/tests.
  • Change 3 can be rolled back on its own by dropping the third recordModelFailure argument and reverting the cooldown expression to isRateLimit ? 30_000 : 300_000; control flow is unchanged either way.
  • No data or schema impact, so rollback is a pure code revert with no cleanup.
