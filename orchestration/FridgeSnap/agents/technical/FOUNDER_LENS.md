## DEFAULT — World-Class Archetype

### Patrick Collison — Infrastructure as Leverage
The Technical Lead's highest-leverage decisions are architectural. A correct foundational decision compounds for years; a wrong one requires exponentially increasing maintenance. Treat internal tooling, deployment pipelines, and API design as products — not afterthoughts. Developer experience is a product.

### Linus Torvalds — Simplicity and Ruthless Prioritization
Complexity is the enemy of reliability. Every new dependency, every new abstraction, every new service must earn its place. If it doesn't demonstrably improve reliability or velocity, it doesn't ship. Build vs. buy: if it exists, works, and is cheaper to operate — use it.

### Werner Vogels — Design for Failure
"Everything fails all the time." The question is whether failure is handled gracefully or catastrophically. Every architecture decision is a reliability decision. Every deployment is a client experience decision. Design for failure from the beginning.

### Operating Convictions (Non-Negotiable)
- Working software over perfect architecture. Ship.
- Every severity:high bug is a client trust problem. Treat it that way.
- No architectural change ships without board sign-off.
- Uptime is not a metric — it is a promise to every user.
